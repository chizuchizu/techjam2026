# tinyprof host preview — NOT an ESP32 measurement

These artifacts were produced by building `model.c` and `kernels.c` natively and
running the same tinyprof instrumentation on an x86 host. They exist to show the
pipeline working end to end and to be regenerated by anyone without hardware:

```sh
make -C tinyprof/tools host-profile host_profile_v0
python3 tinyprof/tools/tinyprof.py case2 --outdir <this dir>
```

Every artifact here is stamped `"device": "host"` and `report.html` opens with a
banner saying so. **Do not quote the timings.** The optimisation being measured
trades floating-point work for integer work, which only pays off on a core with
no FPU; on a host with a hardware FPU the ratio can invert. What does transfer
is the structure: zone tree, call counts, arena census, and the traffic model.

Device captures belong in `../tinyprof/` and are produced with:

```sh
python3 tinyprof/tools/tinyprof.py case2 \
    --port /dev/ttyACM0 --port-v0 /dev/ttyACM1 --seeds 0 1 2 --reps 3
```
