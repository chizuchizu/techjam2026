# opt16/opt17: KB0 head GEMM hand-asm + FFN1 fixed-point Q15 epilogue

Date: 2026-08-29 · device: ESP32-C3 @160MHz, tree = opt17 (3abb0a8)

## opt16 — KB0 (head_q15) 8-MAC inline asm
- `tm_gemm_head_q15` K-loop replaced by hand-scheduled RV32 asm on `__riscv`
  (C path kept for host): per iter loads 1 weight + 8 activations (const
  offsets 0..1792 at K-stride 256B), 8 muls, 8 adds (RAW distance 8 >= 7)
  = 28 instr / 8 MAC, zero MUL stalls, single rb pointer.
- Guarded `#if defined(__riscv) && (K&1)==0` (K=128 at runtime -> asm).
- Measured: 17.1ms -> 13.43ms per head GEMM call (-21.5%).
- Forward: 2.982s -> 2.838s.  Device gate 5/5, host 25/25 PASS, same max_abs.

## opt17 — FFN1 direct Q15 output (integer epilogue)
- New `tm_gemm_core5_q15()`: f1 GEMM keeps an int32 accumulator, folds bias as
  `bq_j = round(bias[j]/g)`, tracks integer `amax = max|acc+bq_j|`, converts
  in place: `q15 = round((acc+bq_j)*QMAX/amax)` via int64 scale with adaptive
  `sa = drop-low-bits` (amax -> 20-bit divisor => 15-16 sig bits, ~1 LSB).
  No fp32 output buffer, no separate amax scan, no separate quant pass.
- Returns `sa2 = QMAX/(amax*g)` — INVERSE scale matching `tm_gemm_amax`
  convention (root-cause of the earlier 5.2 abs failures: returning the true
  max inverted the gelu-LUT and f2 scale, making gelu a ReLU and f2 x100).
- Bias folded in integer; f1 output lands in a16 (input fully consumed in
  pass 1, so in-place Out==Aq is safe); g_buf2 (dead after oproj) is the
  int32 scratch; gelu LUT + f2 then read a16.
- Measured per call: f1 81.5ms -> 54.0ms; gelu 15.6ms (amax+quant merged
  away); f2 unchanged.
- Forward: 2.838s -> 2.701s (-137ms).  Device gate 5/5 PASS
  (max_abs 9.2e-4..1.1e-3), host 25/25 PASS (max_abs 9.05e-4..1.12e-3).
